# Script

個人使用的 Tampermonkey userscripts,主要針對 YouTube / Twitch 的觀影體驗調整。

## 安裝

瀏覽器安裝 [Tampermonkey](https://www.tampermonkey.net/) 後,點下方腳本連結即可安裝;各腳本彼此獨立,可只裝需要的。安裝後由 Tampermonkey 自動檢查更新。

## 書籤小工具

**Hololyzer Superchat**:在 YouTube 影片 / 直播頁按下,於新分頁開啟該影片的 [Hololyzer](https://hololyzer.net/) 即時 Superchat 統計;非影片 / 直播頁則跳提示。

新增書籤,網址欄貼上:

```
javascript:(()=>{const m=/(^|\.)(youtube\.com|youtu\.be)$/.test(location.hostname)&&location.href.match(/(?:[?&]v=|\/(?:live|embed|shorts)\/|youtu\.be\/)([\w-]{11})/);m?open('https://hololyzer.net/kojin/realtime/superchat/'+m[1]+'.html'):alert('這不是 YouTube 影片 / 直播頁面')})()
```

支援 `watch?v=`、`/live/`、`/embed/`、`/shorts/` 與 `youtu.be` 短網址。

## 設定

- **Shorts 右側面板與資訊隱藏**:一律隱藏 Shorts 影片內的頻道、標題、訂閱與關聯影片覆蓋層；在桌面寬視窗預設於右側展開面板並顯示「影片資訊」頁籤，上方依序提供「影片資訊」與「留言」頁籤以及統一的關閉鈕（`ArrowLeft` / `ArrowRight` / `Home` / `End` 可移動頁籤焦點）。每次切換到下一部 Shorts 都會自動重設回「影片資訊」頁籤。全螢幕與窄視窗不自動彈出蓋住影片的面板，但手動開啟說明或留言時仍會顯示頁籤；手動按「×」關閉後不會自動重開，直到手動重新開啟面板或離開再回到 Shorts。
- **Shorts 音量**:游標在影片範圍內時,滾輪向上加 5、向下減 5(0–100);影片外維持原本的捲動/切片行為。`Ctrl` + 滾輪保留瀏覽器縮放。
- **YouTubeLiveClock**:改檔頭的 `FORMAT` 常數(1–6)切換日期格式,選項見檔內註解。
- **YouTubeLiveChatTweaks**:上方漏斗按鈕位於「…」右側，開啟篩選時顯示藍色、關閉時恢復原色；漏斗與重新載入按鈕使用原生圓形 hover 且不顯示提示框。「…」選單依聊天室視窗限制寬高。漏斗切換一般／篩選聊天室，隱藏原本「トップチャット／チャット」選單，介面沿用 YouTube 聊天室的主題配色。上方只顯示「目標用戶」與訊息數；展開「目標用戶」會填滿聊天訊息區，Broadcaster／Moderator／Verified 選項與帳號管理都放在其中，收合後恢復訊息。角色選項（Broadcaster／Moderator／Verified）與帳號包含／排除名單均為全域設定，套用於所有頻道與影片，不再提供單一頻道或單一影片的個別篩選條件（既有舊版設定會自動整併為全域設定）；選「＋ 包含」或「－ 排除」，每次新增一個 YouTube 頻道 ID（`UC…`）、`/channel/UC…`、`youtube.com/@handle` 完整網址或 `@handle`；目標用戶清單固定同時顯示「頻道名稱、`@帳號`、UC 頻道 ID（UCID）」（從瀏覽器快取與現場／已存聊天室訊息補齊，缺少時背景查詢 YouTube 並保存於瀏覽器），搜尋欄可同時搜尋名稱、`@帳號` 與 UCID；頻道 ID 保留大小寫，依發言者 ID 比對，改名不影響篩選。原有中文與日文帳號仍可使用，排除條件優先於角色與包含名單。全域篩選設定儲存在瀏覽器（若瀏覽器封鎖寫入仍會在目前頁面暫存套用），並同步到同一瀏覽器中已開啟的聊天室。SC／會員紀錄與用戶篩選訊息均以影片分開保存於瀏覽器 IndexedDB，從首次收集起保留 7 天且不設則數上限；重新整理或重開同一影片會直接完整載入 7 天內所有紀錄並接續收集，依訊息 ID 去重且不延長原保存期限；開啟時與使用期間依到期時間範圍自動清理到期資料。切回一般聊天室仍持續收集；手動上捲暫停跟隨，按「回到最新訊息」恢復。新增按鈕有明確底色與外框，並與輸入框等高；兩平台都使用 30px 高、4px 圓角的矩形。訊息旁的「…」已移除，點擊帳號開啟 Twitch 布局風格的用戶資訊卡，資訊卡與聊天室等寬，包含頭像、頻道名稱、@帳號、UC 頻道 ID、目前訊息已有的會員／管理員／驗證徽章與原生操作按鈕；名稱與徽章保留聊天室的原生角色配色（會員綠色、Moderator 藍色、頻道主金黃色等）；原生高亮姓名的淺底黑字會改用資訊卡的角色配色，驗證等中性徽章沿用卡片文字色，避免複製黑字到深色背景後不可見；徽章以圖示格列於身分資料下方，不顯示「徽章」標題；@帳號與 UC ID 放在名稱下方，不另隔區塊，名稱、帳號與 ID 依實際文字寬度縮小字體以維持單行，聊天室加寬時恢復原大小，資訊卡的 ggpht.com 頭像與徽章圖片移除尾端 `=s…` 縮圖參數，改用原尺寸圖片；顯示大小仍為頭像 56px、徽章 26px，徽章圖示不額外查詢。用戶資訊卡在開卡時查詢頻道名稱；SC／會員紀錄則在發送者出現在列表中時查詢，使用本次頁面快取並共用同一頻道尚未完成的查詢；載入中或失敗仍可查看帳號與 ID，不影響聊天室收訊息。報告／封鎖沿用 YouTube 原生選單資料、登入權限及確認流程，文字隨 YouTube 語言改變，報告對應所點擊的那則訊息；操作按鈕依圖示與文字內容計算寬度，分別處理報告的 service 元件與封鎖的 navigation 元件，移除兩種原生文字元件與選單項目預留的額外空間。只有點姓名才開卡，點訊息文字不開啟，連結仍可使用；姓名支援 Enter／空白鍵，Escape 關卡。一般聊天室、用戶篩選及 SC／會員紀錄的資訊卡與上方選單展開時，第一次點外部只關閉，下一次才執行底下的操作，同樣支援點擊嵌入聊天室外側。整個篩選面板使用瀏覽器最上層，範圍由聊天室標頭到輸入區定位，不會隨原生聊天摘要縮小或被原生浮動物件遮擋；用戶篩選與 SC／會員紀錄（含搜尋結果及還原的舊紀錄）均可點擊姓名開啟相同資訊卡，卡片顯示在篩選面板上方；姓名支援 Enter／空白鍵，Escape 關閉並將焦點移回姓名，切換列表時關卡。當頁保留原訊息的操作資料；重新載入的舊紀錄仍可查看頻道資訊，但不保留原生報告／封鎖操作。帳號操作提示 3 秒後自動清除，連續操作會重新計時。原有表情複製與重新載入功能可繼續使用。針對一般聊天室前景自動跟隨與原生列表卡住（如限定 `#item-scroller` 內的 `#items`、修正平滑捲動／表情圖片撐高導致 `atBottom` 誤判、視窗失焦解除 `Alt` 暫停或殘留的選單鎖定並沖刷待顯示訊息），以及會員直播等情境下的輪詢中斷／卡死，腳本會依序透過軟性重觸發輪詢、原位重載 continuation 與受節流／輸入保護限制的聊天室重載自動恢復（重播、已結束直播、離線與正在輸入時不動作）。
- **TwitchLiveChatTweaks**:按聊天室上方社群按鈕旁的漏斗圖示切換篩選模式；漏斗按鈕採用與原生按鈕一致的圓形 hover 與左側原生風格 tooltip（支援滑鼠移入提示本體與 `Escape` 關閉）。分割螢幕或窄視窗劇院模式使聊天室排在影片下方（`.right-column--below`）時，保留「實況聊天室」標題列（含收合、漏斗與社群按鈕）以明確區隔直播與聊天室，同時自動隱藏上方所有橫幅（排行榜、贈禮推廣、釘選訊息、投票、預測、Hype Train、提示通知等，並清除訊息區動態預留的上方留白）與輸入框下方的小奇點／忠誠點數／設定／聊天按鈕列，保留聊天訊息、背景收集與「傳送訊息」輸入框（可按 Enter 送出）。上方顯示「目標用戶」、訊息數與聊天紀錄搜尋欄（展開「目標用戶」時自動收合搜尋欄）；發言者若具本地化顯示名稱會同時保留顯示名稱與登入帳號（例如 `偷米 (tommy181933)`）。使用 Twitch 原生回覆功能時，篩選目標自己的發言（含目標之間互回或目標回覆排除名單帳號）會直接顯示於主列表並在上方保留回覆對象引用列（`回覆 @顯示名稱 (帳號)：原留言內容`，並隨 7 天紀錄與編輯狀態一併保存）；若篩選目標回覆的是另一位目前已啟用的篩選目標、且被回覆的原留言未在目前列表內，即使尚未出現觀眾回覆（或已關閉「回覆篩選目標」），也會先在該則上方自動重建一列獨立的「原留言」目標列（沿用已記住的帳號配色，標示 `原留言 名稱: 內容`；尚未有觀眾回覆時隱藏展開鈕，後續若有觀眾回覆則會直接併入同一串並顯示 `▸ N 則回覆`）；一般觀眾直接回覆目前啟用目標的留言則預設收摺，並直接在對應目標留言內容後方以行內按鈕（`▸ N 則回覆`）顯示，若原目標留言未在目前列表內，同樣改依原留言建立獨立的「原留言」目標列搭配行內 `▸ N 則回覆` 分組顯示，各自維持獨立一串而不與前後目標留言混淆；點擊即可在該則下方展開或收合回覆列表，並在篩選畫面開啟期間保留展開狀態（關閉篩選畫面時自動摺疊所有對話串），同時透過 `hidden="until-found"` 支援瀏覽器頁面搜尋（Ctrl+F）自動展開比對中的隱藏回覆。搜尋欄可同時比對登入帳號、顯示名稱、留言內文、表情符號名稱以及回覆引用列的對象名稱／帳號／原文，搜尋結果會直接攤平顯示並保留各則回覆上方的引言列，清空搜尋後恢復收摺清單與先前展開的項目；搜尋不分英文大小寫並支援全形字元，空白分隔的多組關鍵字須全部符合，且會即時隨新訊息或編輯更新。展開「目標用戶」會填滿聊天訊息區，Broadcaster／Moderator／VIP 與預設勾選的「回覆篩選目標」選項也移至其中，收合後恢復篩選訊息。開啟「回覆篩選目標」時，未在排除名單內的觀眾只要直接回覆目前啟用的篩選目標（Broadcaster、Moderator、VIP 或包含名單帳號），該則回覆訊息與目標引用列都會一併收錄並收入對應展開清單；唯 Twitch 原生回覆資料不含被回覆者的徽章，若該名 Moderator／VIP 尚未在本次工作階段或 7 天紀錄中出現過發言，則無法僅憑回覆辨識其身分。角色選項（Broadcaster／Moderator／VIP）、回覆篩選開關與帳號包含／排除名單均為全域設定，套用於所有頻道，不再區分「目前頻道」與「全域」名單範圍（既有舊版設定會自動整併為全域設定）。選「＋ 包含」管理要顯示的帳號，選「－ 排除」管理不要顯示的帳號。排除名單優先於發言者條件：被排除帳號發出的任何訊息（包含回覆篩選目標）都不會收錄或顯示，一般觀眾回覆被排除帳號也不會收錄；但符合篩選條件的目標用戶若回覆了排除名單內的帳號，該目標用戶的發言與其回覆引用列仍會一併保留（即使關閉「回覆篩選目標」亦同）。可新增、搜尋及逐一移除帳號；每次填一個 Twitch 英文登入帳號後按「新增」，多個帳號或無效輸入不會加入。新增與搜尋的標籤和輸入框排在同一行，新增按鈕與輸入框等高、上下對齊，並與 YouTube 使用相同的 30px 高、4px 圓角矩形，目標用戶區可收合以留出聊天空間；帳號操作提示 3 秒後自動清除，連續操作會重新計時。整個篩選面板使用瀏覽器最上層，改依聊天室標頭至輸入區固定定位（不隨原生排行榜、釘選或投票橫幅縮放跳動，收合聊天欄時自動隱藏），不會被原生用戶卡、徽章彈窗等物件遮擋，收合目標用戶管理後的訊息列表也一樣；切回一般聊天室後恢復原生互動。全域設定儲存在瀏覽器，並同步到同一瀏覽器中已開啟的聊天室；切回一般聊天室仍持續收集符合目前勾選條件且未排除的訊息，保留表情與徽章；未勾選身分或排除名單帳號不再收錄，避免無關訊息佔用紀錄額度；VIP 依 Twitch 原生 VIP 徽章與徽章資產識別。列表與搜尋結果依訊息日期顯示跨日分隔列（`YYYY/MM/DD`）以區分不同天的發言。手動上捲暫停跟隨、點開回覆清單與達到 1000 則上限淘汰舊訊息、或關閉後重新開啟篩選畫面時，皆會以目前閱讀列為錨點保持可視位置不跳動，按「回到最新訊息」恢復自動捲動。篩選紀錄按頻道（或 VOD 影片 `vod:ID` - **YouTubeLiveLayout**:`PRIMARY_RATIO` 控制寬視窗中播放器與聊天室的寬度比(預設 0.75);頁面寬度低於螢幕可用寬度的 `MAX_STACKED_VIEWPORT_RATIO`(預設 0.75),且側欄低於 `MIN_SIDE_CHAT_WIDTH`(預設 400px)時,聊天室改排在影片正下方並使用完整寬度。影片下方的標題與操作列使用播放器欄的完整寬度，避免原生右欄擠壓資訊區造成提早換行。
- **BahamutForumDarkTextFix**:依每段文章元素的實際背景亮度判斷是否處於黑暗模式。僅在深色背景（相對亮度 `< 0.35`）下介入，使未著色元素改回繼承父層顏色，並從原始 `<font color>` 與行內 `style.color` 重算對比度：深灰／黑色正文平滑對應為深色模式淺灰白字體，彩色文字保留原色相並沿 HSL 亮度軸調整至至少 5:1 對比度；原本就是淺色底的亮色區（如黃底標記）則維持深色文字。切換回淺色模式時還原原始行內樣式，並略過 `[contenteditable]` 編輯區避免寫入發文內容。
- **YouTubePlayerTweaks**:首次以滾輪或原生滑桿調音量後會啟用音量曲線，原生音量 25/50/100 對應約 18.75/75/300% 的輸出。同一分頁內切換影片會繼續套用，新的影片元素會接回增益；重新整理或新分頁需再次調音量啟用，啟用狀態不永久儲存。`MAX_VOLUME_GAIN` 控制最高增益(預設 3 倍)。`MAX_DVR_SECONDS` 為 DVR 回看上限(預設 7 天);`LIVE_CATCHUP_RATE` 控制追直播速度,`LIVE_CATCHUP_TARGET_BUFFER` 為可播放緩衝的追平門檻(預設 0.5 秒)。達到門檻時會停止追平並恢復原本速度。自訂控制鈕 tooltip 支援滑鼠移入提示本體保持顯示及按 `Escape` 關閉。

YouTube 一般訊息與篩選訊息均以「頭像、名稱、徽章、內文」同列顯示；頭像配合文字行高縮放，長訊息換行後可使用頭像下方的完整寬度。聊天室標頭的皇冠 XP 指示器靠左顯示。篩選列表中的高亮名稱會使用角色配色，避免複製原生淺底標籤的黑字後，在深色背景上無法辨識。

YouTube 與 Twitch 的「目標用戶」預設收合，按標題才展開管理。兩者均即時收集訊息，同一批 DOM 變動中的同一則訊息只解析一次；YouTube 並在解析早期先過濾未納入收集範圍的一般聊天訊息、快取發言者色彩與設定檔讀取結果、僅掛載可見列並對訊息列套用 `content-visibility: auto`（搭配 `contain-intrinsic-size` 避免捲動跳動）與延遲 DOM 建立、快取 SC 搜尋文字與索引查詢，並以二分搜尋追蹤閱讀錨點；Twitch 亦跳過聊天室子樹的播放器監視、僅掛載可見列並套用 `content-visibility: auto`，另如 YouTube Shorts 面板過濾無關與自身頁籤欄變動及略過未變更的狀態寫入、YouTubeLiveLayout 待機畫面隱藏時略過背景樣式查詢及略過未變更的樣式寫入，藉此減少重排與重複掃描。開啟大量保存紀錄時依每 50ms 預算讓出主執行緒（優先使用 `scheduler.yield()`）；聊天與管理介面提供明確 `<label>` 綁定、`<search>` 地標、卷軸對比度與 `overscroll-behavior: contain`、資訊卡微動效（尊重減少動態偏好），且只在儲存失敗時將狀態欄標為 `role="status"`。篩選畫面每幀合併更新，只處理新增、修改及淘汰的紀錄，切換篩選條件或重新開啟篩選時才完整重算。背景分頁繼續收集並保留紀錄，回到前景後合併更新篩選畫面；YouTube 一般聊天室在背景收到訊息時直接捲至最新，切回前景會再次對齊底部，手動上捲暫停跟隨時則保留位置。兩平台皆在開啟時直接完整載入保存期限內的紀錄（Twitch 每頻道最多 1000 則、最多 7 天；YouTube 完整保留 7 天且不限則數）；記憶體保留最近 5 個頻道，保存期限內的紀錄仍保留在瀏覽器。

## 腳本間的關聯與已知取捨

- **LiveClock 依賴 PlayerTweaks 的 DVR 解鎖**:直播「經過時間」取自進度條位置,只有在 DVR 視窗涵蓋整場直播時才等於真實經過時間;超過 13 小時的直播需要 PlayerTweaks 放寬的回看視窗才準確。
- **字幕功能分工**:PlayerTweaks 用 CSS 隱藏字幕「按鈕」,AutoDisableSubtitles 負責關閉字幕「狀態」,兩者互補而非重複。
- **TwitchPlayerTweaks**:與 YouTube 使用相同音量曲線，原生音量 v（0–1）乘上 3v 增益；顯示值 25/50/100 對應約 18.75/75/300% 的原生輸出。滾輪仍每次增減 5，顯示範圍維持 0–100；首次滾輪或原生音量控制操作才啟用，之後原生滑桿變動也會同步。同一分頁切換頻道或影片、替換 video 元素仍會套用，回到舊元素會重用來源節點；多播放器共用一個 AudioContext、各自持有增益，移除的播放器會斷開音訊節點。重新整理或新分頁需再次啟用；沒有可用 Web Audio、跨來源或受保護媒體會保留原生音量。截圖按鈕的 tooltip 同樣支援滑鼠移入提示本體與 `Escape` 關閉。`VOD_CLOCK_FORMAT`（1–6）可設定 VOD 直播時間格式；進入實況存檔（`ARCHIVE`）VOD 頁面（`/videos/影片ID` 或 `/頻道/video/影片ID`）時透過 Twitch GQL 取得開播時間（不套用於精華／上傳影片），顯示於播放器時間旁並隨播放與跳轉更新。

- **YouTube / Twitch 截圖**:播放器就緒後預先啟動背景編碼 Worker,截圖保留原解析度 PNG,剪貼簿與下載共用同一份圖片。PNG 完成後直接由瀏覽器下載,省去 Tampermonkey 下載流程的等待;檔案存到瀏覽器設定的下載位置,不再自動放入 `ScreenShot/` 子資料夾。不支援相關瀏覽器功能時自動使用相容流程;PNG 編碼與瀏覽器存檔仍需要時間。
- **PlayerTweaks 會覆寫頁面的 `JSON.parse` 並攔截 `ytInitialPlayerResponse`**:這是 player response 送達的僅有兩條路徑。若頁面上先前已有其他攔截器(如 uBO scriptlet)掛在 `ytInitialPlayerResponse` 的存取器上,會串接保留其 getter／setter 並持續轉發寫入;若無既有存取器,則在首次攔截後恢復為一般屬性。
- 所有腳本都依賴 YouTube / Twitch 的內部 DOM 結構與非公開 API,**上游改版隨時可能使功能失效**,失效模式以「靜默不動作」為主,不會弄壞頁面本身。

## 本機驗證

使用 Node.js 內建測試工具,不需要安裝額外套件:

```sh
node --test tests/*.test.cjs
```

測試涵蓋播放器追平與速度恢復、截圖 Worker 及失敗回退、SPA 導覽與等待清理、聊天室跟隨、時鐘重建、版面初始化、字幕與畫質就緒、網址跳轉，以及巴哈姆特哈啦區黑暗模式文字配色與主題切換還原。私人站點腳本與對應測試由私人 repo 管理。

測試在 Node.js VM 中模擬瀏覽器 API;實際網站 DOM、CSS 排版、剪貼簿權限與 PNG 像素仍需在瀏覽器驗證。

Twitch 篩選聊天室另有 `tests/fixtures/twitch-chat.html` 測試頁，搭配本機靜態伺服器將該頁提供在 `/fixture_channel`，並將新腳本提供在 `/TwitchLiveChatTweaks.user.js`，可驗證 VIP／角色／回覆篩選與帳號管理（含目標回覆排除帳號、觀眾回覆於目標留言後方顯示行內 `▸ N 則回覆` 展開清單、未載入原留言改以獨立「原留言」目標列＋行內按鈕分組／目標互回補建及排除帳號情境）、訊息清理、聊天室重建、頻道切換及跨分頁同步，並可用「切換分割螢幕模式」確認 `.right-column--below` 保留聊天室標題列並隱藏上方橫幅與輸入區底部列，以及用「顯示遮擋測試物件」確認整個篩選面板保持最上層。此頁不會傳送聊天訊息。

YouTube 篩選聊天室有 `tests/fixtures/youtube-chat.html` 測試頁，將該頁提供在 `/live_chat?v=fixture_video`，並提供 `/YouTubeLiveChatTweaks.user.js`，可驗證角色與帳號篩選、排除優先、DOM 清理／重建、單列排版、聊天模式選單隱藏及用戶資訊卡，並用「顯示遮擋測試物件」確認整個篩選面板保持最上層。資訊卡使用模擬的名稱查詢、原生事件橋接與操作確認視窗，頁面底部顯示請求次數；`failProfile`、`failMenu`、`profileDelay`、`menuDelay` 及 `signedOut` query 參數可驗證失敗、延遲與未登入狀態。「切換聊天摘要」可重現摘要占用高度，確認篩選區不跟著縮小；`longName` 可驗證超長頻道名稱與帳號保持單行，「切換聊天室寬度」可檢查字體隨可用寬度調整；`highlightedOwner` 重現高亮頻道主的淺底黑字，搭配 `light` 可驗證深淺主題的名稱與徽章配色。`channel` 可指定測試頻道，以驗證全域篩選名單跨頻道共用與各影片訊息紀錄隔離。此頁不會傳送聊天訊息或執行實際帳號操作。

聊天室上方另有獨立「SC／會員」按鈕，點擊切換 SC／會員紀錄，再點一次回到一般聊天室；與漏斗篩選按鈕可直接切換。SC 紀錄顯示時間、發送者、原幣別金額與留言，也保留沒有留言的 SC，不套用目標用戶或排除名單。一般聊天室與用戶篩選模式下都會持續收集已載入的 SC，與篩選訊息一起按影片保存在目前瀏覽器 7 天；重新整理、關閉後重開都能接續，回放以訊息 ID 去重，未載入的歷史 SC 不會補抓。測試頁的「新增 SC」與「新增無留言 SC」可驗證獨立列表、金額與切換行為。

SC／會員按鈕沿用 YouTube 原生支援按鈕的鈔票圖示；原生按鈕尚未載入或回放沒有購買按鈕時，使用已從實際聊天室確認的相同 SVG。紀錄保留原訊息的背景、金額底色與文字配色，不以金額或幣別推算顏色；測試頁的「新增七色 SC」可檢查各色級距。

「SC／會員紀錄」也會自動收集會員加入（`membership`）、會員里程碑（`milestone`）與會員贈禮（`membershipGift`），不記錄獲贈會員公告。里程碑保留累積月份、會員等級和完整留言；贈禮保留送禮者、數量與公告文字。不論是否開啟紀錄列表都會收集，與 SC／Super Sticker 一起保存 7 天，重開接續並依訊息 ID 去重；一般會員的普通聊天仍依原本的用戶篩選條件處理。測試頁提供三種會員事件按鈕與獲贈會員的忽略測試按鈕。

用戶篩選的「目標用戶」內提供預設開啟的 Verified 選項，與 Broadcaster、Moderator 並列，為全域設定與跨分頁同步。已驗證用戶已載入的發言會持續收集，取消勾選後再開啟仍可查看 7 天保存期限內已收集的訊息；全域排除名單一律優先。只依 YouTube 原生驗證徽章與驗證圖示資料辨識，不依帳號名稱或會員徽章判斷，也不將一般已驗證用戶發言加入 SC／會員紀錄。測試頁的「新增已驗證用戶訊息」可驗證。

SC／會員紀錄的發送者顯示為「真正的頻道名稱 @帳號」。依 UC 頻道 ID 查詢列表中可見的發送者，同一頻道共用查詢與本次頁面快取，最多同時查詢 4 個頻道；載入中或失敗時保留原本名稱與 @帳號，不阻擋紀錄收集。取得的名稱會隨 7 天紀錄一起保存，重開可立即顯示，查看時再更新。一般用戶篩選的普通訊息維持原顯示方式，帳號篩選仍使用原本身分與 UC ID。

SC／會員紀錄上方提供搜尋欄與類型／色彩篩選勾選列，可搜尋頻道名稱、@帳號、留言、金額與會員事件文字，不分英文大小寫並支援全形字元；多個關鍵字以空白分隔時須全部符合。篩選列包含「會員加入」、「會員里程碑」、「會員贈禮」與「超級留言」搭配對應七種顏色方塊（Super Sticker 依色票級距併入「超級留言」篩選），預設全部勾選，勾選或取消「超級留言」可連動切換七個顏色，部分勾選時顯示不定狀態（indeterminate）；勾選狀態會儲存在瀏覽器並跨分頁同步，重新整理或重開影片會保留先前勾選條件（若瀏覽器封鎖寫入則僅保留至本次頁面結束），不影響目標用戶篩選設定。搜尋與類型／色彩篩選可同時疊加並直接涵蓋目前影片 7 天保存期限內的所有完整紀錄（無分頁或「載入較早結果」限制）；新增訊息與內容更新會同步反映，清空搜尋或恢復勾選即還原列表；切換一般用戶篩選不套用 SC 搜尋與類型篩選條件。

搜尋結果旁的「定位」可清空搜尋並回到完整 7 天 SC／會員紀錄，將選中的訊息捲到列表中央並標示 3 秒，同時維持其前後完整 SC／會員事件上下文，保存期限維持不變。定位後暫停自動跟隨，手動捲到最下方或按「回到最新訊息」可恢復。

在同一頁面切回原生聊天室或切換 SC／用戶篩選時，各列表分別記住閱讀的訊息、捲動位置與是否跟隨最新訊息；重開列表回到原位置，期間收到新訊息也不強制跳到底部，聊天室元件重建時同樣保留。SC 金額只顯示貨幣與數字，不再加上「SC」前綴；會員里程碑的月份與會員等級合併成一排，留言維持下一排。既有保存紀錄也套用新的金額與會員排版。

超級貼圖（Super Sticker）也會自動收錄於 SC／會員紀錄，保留原生金額、貼圖與配色，同樣保存 7 天並支援重開接續、搜尋與定位。貼圖尚未載入時可從 YouTube 的貼圖資料取得圖片與說明，後續圖片更新會依原訊息 ID 更新，不重複收錄；可搜尋「超級貼圖」、貼圖說明、發送者或金額。測試頁提供「新增超級貼圖」按鈕。

正在跟隨最新訊息時，貼圖、圖片或名稱載入造成訊息高度改變，列表會在下一畫格重新貼齊底部；搜尋結果同樣適用。延後的程式捲動事件不會被誤認成手動上捲。手動上捲或定位後仍保留閱讀位置，按「回到最新訊息」可恢復跟隨；回到前景時也會補正背景期間的高度變化。

Twitch 貼圖的原生透明按鈕不再套用篩選面板的紫色操作按鈕樣式，保留原有貼圖尺寸與背景。7 天紀錄保留文字、作者配色、徽章與貼圖（包含 picture/srcset）；還原內容為靜態節點，不保留原生事件或可操作按鈕。瀏覽器無法寫入紀錄時會顯示保存失敗提示，當頁仍繼續收集。
